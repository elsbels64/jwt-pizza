# Incident: 2026-04-08-1 13-45-22
## Summary

Between the hour of **13:45** and **13:47** on **2026-04-08**, **4** users **were unable to order pizza**. The event was triggered by a **the jwt pizza factory website generating chaos and refurning 500 for all calls to order pizza** at **1:45**. The failure contained response 500 returned from the jwt pizza factory due to the chaos type being set to fail.

A bug in this code caused the website to no longer be able to sell any pizzas. The event was detected by an increase in the Pizza logs that caused an **alert that monitors the number of errors >=500**. The team started working on the event by looking at the alert and then looking through the logs sent by the jwt pizza website. This **SEV-1** incident affected **everyone trying to order**.

There was further impact as noted by **several alerts and a few calls to the TA's** that were raised in relation to this incident. Additionally, **several hours of the developer's time** was spent as a result of a faulty alert that relates to this incident

## Detection

The **alert** related to this incident that detects response codes over 500 **had a false positive** shortly before this incident. This **paged the jwt pizza developer**, Elise W. before there was actually an issue. This also complicated solving the issue because the developer was trying to solve issues that didn't exist yet.

Elise W. **fixed the false positive alter** by doubling the threshold of the alert (from 10 500 responses in 5 minutes to 20 500 responses).

At **13:45** the alter went off a second time. The developer looked at the logs for requests that had a 500 response code and found that all **POST** requests to **/api/order** were failing. In the response to these requests was a section called **followLinkToEndChaos** that had the value **https://pizza-factory.cs329.click/api/support/e1dcdefbb485405696743e85eb191d89/report/l2oyixsa**. Following the link reset the chaos state to calm and resolved the failing jwt pizza factory.

To avoid false time-wasting false positives in the future, Elise W. will **set multiple levels for each alert**, so that the dev team is still informed when something is out of the ordinary, but are only paged when there's a serious issue. 

In order to avoid unnecessary error 500 responses and improve customer experience, Elise W. will also add checks to the front end code in order to **stop users from trying to order over 22 pizzas at once** which is a number we know the jwt pizza factory can't handle.

Elise W. will also **look into other options for pizza orders** besides jwt pizza factory for pizza orders.

## Impact

For **3 minutes** between **13:45** UTC and **13:47** UTC on **04/08/26**, users were **not able to order pizzas**.

This incident affected **all customers** trying to order (**100% OF dashboard USERS**), who experienced failed pizza orders.
